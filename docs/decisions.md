# Decisions

Why the language is the way it is, a row for each decision, and what the July specs have that isn't built.
`language.md` is the reference for what exists. Add a row here when the language changes.

## The language

Newest first. "Why" is the reason at the time, so these can be revisited.

| Date | Decision | Why |
|---|---|---|
| 2026-11-16 | A space ends a denominator: `1/2 π` is π/2, and `1/2π` is still 1/(2π) | Kris typed a fraction times π from a Desmos graph, `(k - 1)/N π`, and the π went under the bar, with a space or without. Desmos draws the bar, so there the question never comes up. Factors right against each other are one term, which is why `1/2π` reads as it does, and a space is where a reader sees the term end. Nothing in the corpus changed meaning |
| 2026-11-16 | A name that isn't a function multiplies the parentheses after it | `π(t - 1)` was an unknown function `π`. Desmos calls a name only when it is a function and multiplies otherwise, and pasted formulas rely on it. The compiler decides, since it knows what each name is, and it gives a power after the parentheses to them alone, as the product reads. A name that is nothing at all is still an unknown function, with its suggestion |
| 2026-11-16 | The standard functions are built in: `sec`, `csc`, `cot`, the inverse trigonometric and hyperbolic functions, `log`, `ceil` and `round`, and they and `sin`, `cos` and `tan` take complex numbers | A formula pasted from Desmos read as `arctan(x)` and then didn't compile, because the LaTeX reader kept a name the language lacked. Reviewers playing a teacher and a hobbyist hit it first, and Kris said all the standard functions should be there. Each compiles to functions the evaluators and shaders already have, as the hyperbolic ones do, so there's one formula for the derivative, the CPU and the GPU, and nothing new to keep in step |
| 2026-11-16 | `log(x)` is base 10, `arccot(x)` is between 0 and π, and `round` sends a half away from 0 | Each is what Desmos does, and Desmos is where most pasted formulas come from: the LaTeX reader already read `\log` as base 10. `arccot` as `arctan(1/x)` would jump at 0. `ln` stays the natural logarithm |
| 2026-11-14 | The document names its poster: `poster { time: 3.5, roll: 0.6 }` | A page shows a still until a figure's first frame, and a link's preview shows nothing else. Which moment tells the most is about the figure, and the Möbius page already said it in script, as `figure.time = 3.5`. A sheet's `style figure { poster: 3.5 }` was the alternative: it lets a video's sheet and a page's differ, and can't set a param. Kris chose the document |
| 2026-11-14 | A compiled figure carries the colors its sheets name | A page takes its colors from its figure's sheets, and a compiled figure has no sheets to ask. They're in what the build writes down, too, so a page can use them before the figure runs |
| 2026-11-14 | A point can have a `z`, and a mark draws it looking down z | Kris wants the blog's 3D figures in Pencil. All three are orthographic strokes and flat fills, with no lighting, so a third coordinate that drawing drops covers them, and a figure with no `z` doesn't change. The projection is worked out when a mark is compiled, so no renderer learned anything new |
| 2026-11-14 | A point in space isn't a complex number | A point in the plane multiplies and goes through `exp`, which is why the lattice and the Möbius figures are short. None of that has a meaning in space, so it's an error there, and space gets only what a vector has |
| 2026-11-14 | The far side of a surface is a sheet's choice, read from `self.z` | The site's tube split each row into front and back paths at the nearest of 48 samples, which Kris found jumpy and hacky, and wanted as a style: "something like z < 0". The figure says where each point is, and puts the tube's axis at z = 0, so z < 0 is the side facing away however far it's rolled. The sheet fades it. The stroke is cut where the style changes, so the cut is at the crossing |
| 2026-11-14 | A stroke's `opacity` can vary along it, and overlapping parts show the most ink | A stroke had one opacity. Varying it per part, drawn into the stroke's coverage, costs no new texture or pass, and since coverage already combines by maximum, a near strand always shows over a far one it crosses, with no sorting by depth. The cost: the color can't vary along a stroke, only how much of it there is |
| 2026-11-14 | `self.z` is the figure's `z`, not the distance from the eye | With the view turned by `yaw`, distance from the eye mixes in `x`, and isn't which side of the tube a point is on. Which side faces the reader is the surface's normal against the view, and for a tube about the x axis that's the sign of `z` for any `yaw` short of a quarter turn. A figure knows its surface, so it's the one to say |
| 2026-11-14 | `use "file"` puts another file's statements in the figure, in the one set of names | Kris: the limaçon explainer's 32 beats were already a lot in one file, and helpers are written again in each figure. One namespace, because the parts of a story aren't independent: a later part drops and moves what an earlier one drew. The alternative, modules with their own names and imports, would make every part list what it takes from the others. Libraries with their own names are the next step, and build on this |
| 2026-11-14 | A used file joins once | So two parts can both `use` the helpers they need without defining them twice. Nothing has needed the same file twice, and its names would collide if it did |
| 2026-11-14 | The core says which files it needs and a host reads them | The same core runs natively and in a page, where reading is a fetch. A name is the path from the using file, so the command and a page find the same file |
| 2026-11-14 | A param's range can follow other params, and the figure keeps every param in its range | The lattice's `p` counts steps along a side of length `q`, so `p ≤ q`. The lattice's page said so in script, and the site's controls, built from what the figure says of itself, had no way to know, so `p` ran past `q`. A limit like that is part of what the param is, as its step is, so it's in the document: every host gets it, and so does a video. The core enforces it, and not only a control, because `q` can move under a `p` nobody is touching. A page asks for the range as it stands instead of being handed the expression, so it needs no evaluator. An end reads only numbers and params, which is what the lattice needs and keeps the widest range findable. Before this a binding could drive a param past its range, and only a drag was held to it. No figure did, and a test now says none does |
| 2026-11-14 | A value can read a beat written after it | Splitting the explainer by part put `let phi`, in part 2, before the beats of parts 3 to 6 that move it. Beats keep their order, so one needed early brings the beats and pauses before it. The compiled figure differs from the single file only in the order of its bindings, and its frames are the same |
| 2026-11-12 | An unknown name says what was likely meant | A name is only ever itself, so `onetwo` and a half-typed `ToCo` are errors, not the splits GeoGebra makes by what happens to be defined. The error suggests instead: a defined name the typed one starts, or is a typo or two away from, or a split into defined names, as "did you mean `one two`?". Built-ins, the figure's own functions and a sheet's names are all suggested |
| 2026-11-12 | Constants and built-ins take MathJSON's names | Kris wants expressions to conform to MathJSON, and pastes to read as they do in the Compute Engine. So `Imag`, `Conj`, `Arctanh` and `Length` became `Imaginary`, `Conjugate`, `Artanh` and `Abs`, `i` is `ImaginaryUnit`, MathJSON's constant names read as themselves, and `e^w` is `exp(w)` so Euler's identity holds exactly. `π` and the other constant glyphs stand alone, so `e^(iπ)` reads as written. The differences that stay are listed under MathJSON |
| 2026-11-12 | `e` is Euler's number, until a figure takes the name | Kris pasted an expression with Euler's `e` and got an error. GeoGebra reads `e` as Euler's until something takes the name, then rewrites the existing `e`s as `ℯ`, so naming three circles changes what a paste means. A document here has one scope, so taking the name is one explicit statement that applies to every `e` in the figure, and nothing is rewritten behind the reader's back |
| 2026-11-12 | A constant is a default a figure can take the name of | A letter is a constant in one field and a variable in another, and Desmos loses `r` and `t` once a figure assigns them. Here `let pi = …` simply wins, in the document and its sheets. The compiler writes the constant as MathJSON's `Pi`, so a figure's own `pi` is an ordinary name to the CPU and GPU paths alike, and `pi` and `π` become one symbol |
| 2026-11-12 | Factors side by side multiply, tighter than `/` | Kris wrote `2π` and it didn't parse, and pasting from Desmos brings `2(x+1)` and `a b`. Binding tighter than `/` reads `x / 2π` as the x/(2π) a reader means. Names stay many letters, so juxtaposed letters are still one name, and a space is how to split them. The corpus parses exactly as before |
| 2026-11-13 | The LaTeX reader is tested on real graphs | 14,764 expressions from 583 saved Desmos states: 86% read, and all of them parse back as Pencil. They showed what the made-up tests missed: `A.x` and `P.real`, `\tan^{-1}` for arctan, `\log` as base 10, calls to functions another line defines, and `\frac{d}{dx}`, which had read as a product. The rest are things Pencil doesn't have: lists, piecewise, derivatives, `with`, regressions and 3D points |
| 2026-11-13 | A name has one subscript | `f_{X175}` became `f_X_175`, since the rule that makes `x1` into `x_1` ran again on a name that already had a subscript, and it renamed square's `length_z2` |
| 2026-11-12 | Values and functions can be written after they're used | Kris: having to define complex functions first puts the in-the-weeds detail before the big picture. Use before definition should be an error only where order means something: what's drawn on top, and the timeline. So a value is pulled forward to just before its first use, and a figure that compiled before compiles in the same order |
| 2026-11-13 | A sheet says what a label shows of its value: `text: expr = value` | Kris wants labels that show `expr = value`, and wants the sheet to choose between a label's words, its expression and its value, with the number's formatting. So one figure can be read with names in a post and with values while it's being worked out. It's written as it reads, and replaces `{expr=}` in the text, which was a day old and put a sheet's choice in the document |
| 2026-11-12 | A label can show a point, and the sheet says how | Kris wrote `label root at (0,0)` for a cube root of unity and got nothing: a label without text drew nothing, its name collided with the value's, and `{root}` only took a number. A point and a complex number are one value in Pencil, so whether `(−0.5, −0.87)` reads as a point, `−0.5 − 0.87i` or `e^(−2πi/3)` can't change what it is, and that makes it the sheet's. `point` is the default because it never misreads a geometric point as a complex number |
| 2026-11-12 | Pasted LaTeX becomes Pencil text, not a second syntax | Kris pasted Euler's identity from Desmos and got an error. Reading LaTeX as it's pasted keeps one syntax in the file, shows what each formula became, and lands on the same names and products that typing would. Letters run together multiply because that's what LaTeX means, and a letter before parentheses calls only a known function, because that's how Desmos decides |
| 2026-11-12 | An `em` follows the reader's text-size setting | The site's design system sizes labels by role in screen pixels (name 17, note 15, tick 12), which zoom scales but a larger default text size doesn't. Labels are text, and a reader who needs bigger text needs them bigger too. So pages set their text in `rem`, and `<pencil-figure>` watches a 1em box and redraws when it changes, though the figure's size doesn't |
| 2026-11-12 | A subscript is written one way: `x1`, `x₁` and `x_{1}` are `x_1` | They were three names and an error, while Desmos, LaTeX and a reader take them as one. `x_1` is MathJSON's spelling and has a typed form. Names a page passes to `<pencil-figure>` go through the same rule, so a page can say either |
| 2026-11-12 | `tau` and `τ` aren't constants; write `2·π` | τ is a variable as often as a constant, as in bipolar coordinates' (σ, τ), and a constant's name can't be declared by `let` or `param`. Hearts only worked because a function's parameters are substituted before constants are read. Constants a figure wants beyond π belong in a library it asks for, which is open |
| 2026-11-11 | A sheet can define functions | Kris wrote a `glow` in a sheet and got "`glow` doesn't take [Real, Real]": a sheet's `fn` was parsed and then ignored, so its calls reached the type checker as unknown. A falloff or an easing is a sheet's business as much as a color is, and `fn` is how a document already says it, so sheets now take the same statement, and a call to a function nothing defines says so |
| 2026-11-11 | A focus can follow a choice, and beats with no lengths can have one | Bounds' last beat is about whichever flower the reader's case closes, and the other should recede. Which one is the document's to say, so the focus follows the choice by an option's name, and the sheet only says how receding looks. Its tags became what each beat is (`boundary`, `middle`), not a color, since the sheet decides colors |
| 2026-11-11 | Any property can be `none`, and `dash: 0` is solid | Kris wanted one solid ray among bounds' dashed ones, tried `dash: none` and then `dash: 0`, and neither worked: nothing could take back an earlier rule's dash, and a dash of 0 drew nothing at all. Both now do what he tried |
| 2026-11-11 | A choice's options can have names | Bounds chooses which angle is a q-th of a turn, and its options are the two values of θ that make it so. As written they're formulas, which say nothing to a reader, while the cases have names, p = 0 and q = 2p, which the captions use. A name and a value go together, so a name rides on the option, and a choice of bare names still waits for a figure that needs one |
| 2026-11-11 | Beats with no lengths share the `duration` | Bounds said its timing twice, in `duration 30` and in `bind beat = min(floor(time / 3), 9)`, so any other duration, or the playground's default loop, cut beats off. Kris expected the beats to share the duration, which says it once. They stay whole steps, so `self.age` keeps its meaning, and the same change gives `beat` its range by name: it had gone to the first param, which in bounds was `q` |
| 2026-11-11 | A param can be one of a list of values, with no enums | The Doyle spiral's shader picks which of ω, 1 and 1 + ω to count arms along, and switches on the pick in two places. Both follow from the direction itself, so a choice of values lets the math use the pick, where an enum would need matching. The options' text labels a page's control, as the site's `{ω, 1, 1 + ω}` comment does |
| 2026-11-11 | A param can have a `step` | Kris added `N` to the limaçon in the playground and found no way to say it counts. A step is part of what the param is, as a type would be, so it belongs in the document and not in a page's control: the value snaps wherever it comes from, and a page reads the step to build its control. The integer params in the corpus say `step 1` now |
| 2026-11-11 | An error names the file it's in, the document or which sheet, as well as its line and column | A sheet's error came back with the sheet's line and no file, and `pencil` printed it after the `.pen`'s path. The playground has to put an error at its place in the right editor |
| 2026-11-09 | Lengths have units: a bare number is the figure's own, `px` a design pixel and `em` the reader's text size | Pages shrink a figure to fit, and its strokes thin with it as an SVG's do, which reads fine. Its labels shrinking too is what made it hard to read, and the blog keeps them a screen size. Saying which frame a length is in, rather than a hidden rule that labels are different, keeps a title that should scale and a hairline that shouldn't expressible. And all three are lengths, so they mix |
| 2026-11-09 | A figure's design size is a sheet's `style figure`, not its viewport's | How big a figure is drawn isn't its math: a video wants 16:9 and a page wants its column. Panels already took theirs from a sheet. A page can work out the shape when it's built, from the document and its sheets, and write it into its markup, so nothing moves as the figure loads |
| 2026-11-08 | A leader is drawn with its label, by each renderer, not by the shader | Only the renderer knows where a settling label ends up and how wide its text really is, and the shader and the oracle both skip labels. `frame::leader_ends` is the geometry, and the page repeats it in a few lines |
| 2026-11-08 | A term's name is its identity and a tag, and what it prints is separate | The roulette's arms and their terms have to share a color and a focus, and `term.2ab` can't be a selector. A name says which term it is, and the text can be anything |
| 2026-11-08 | `trim` cuts a stroke where it becomes segments, and a circle with one is drawn as a line | The GPU and the CPU oracle share those segments, so they can't disagree, and the shader needs nothing new. A curve is cut along its parameter, since that's the order its math goes in, and fully drawn it's the curve as it was, so a loop's dashes don't jump as it closes. A circle keeps only its center and radius, so it can't start at the point it was drawn through yet: a compass circle can be written as a parametric curve that does |
| 2026-11-08 | Beats can have lengths, and `show`, `drop`, `focus` and captions all follow `beat` | `006-square` kept absolute times in two places, and its sheet had to know the document's own names for its fades. Lengths compose, so one change moves what follows, and narration can retime them later. Working everything out from `beat`, not seconds, means a reader stepping, a video and a pause all agree: nothing moves while the figure holds (`docs/plan-explainer.md`) |
| 2026-11-08 | A parametric range can run down | An angle's arc is `0..t`, and `t` is negative half the time. Such a range used to draw nothing, without a word. Running from the first bound to the second keeps the order `trim` draws in, so an arc grows from the side it's measured from |
| 2026-11-08 | A value that holds for the whole figure can't read `time`, and a state can't write a term twice | Both used to fail without a word. A viewport bound was worked out once, at time 0, so `x: -time..time` sat still, and a second `+` took the first's place, so `a + b + c` drew `a b + c` (`docs/plan-explainer.md`) |
| 2026-11-06 | A view keeps equal scales, showing more rather than stretching | Kris: distortion spends a reader's budget fast. A 0.07% stretch also moved a near-straight circle by tens of pixels, since its center and radius were scaled differently. Unequal axes would have to be asked for, and nothing asks yet |
| 2026-11-06 | Bindings run in dependency order, not the order they're written | `bind b = grown` failed at runtime, since a bound param ran at its `param` line, before a later `let`. A real cycle is now an error when compiled. A name still has to be written before it's read |
| 2026-11-06 | `fast.rs` works out a repeated piece once per sample | Inlining copies arguments, so a complex figure repeats itself many times over, and Bipolar Hearts took 18 ms a frame. It's 2.4 ms now. Setting any value starts a new generation, so nothing stale can be read |
| 2026-11-06 | A curve doesn't join two samples across a jump | Bipolar Hearts' coordinate circle goes through infinity as it turns into a line. At the deepest subdivision a chord can still be far from flat, and then it isn't the curve: it's the two sides of a pole, and drawing it flashed a false line across the figure |
| 2026-11-06 | A segment's normal is its own, except at a cap | The way from a pixel to a line was also its direction, but with the pixel center almost on the line that's only rounding error in the shader's single precision. A thin stroke's coverage depends on direction, so the GPU drew those pixels too dark, by up to 18/255 in a test made to show it, and the CPU oracle matched a 400 × 400 supersample. Squaring map's square grid had two such pixels. |
| 2026-11-06 | A point is a complex number, and a number is one on the real axis | Half of Kris's 583 Desmos graphs use complex mode, and `T(w) = 2πi·w / A` should be writable that way. It also means i turns a thing 90°, as he teaches it. No second type, and it compiles to plain numbers. The cost: a stray `i` isn't an error |
| 2026-11-06 | Panels with the same systems share their answers | They solve one question, and solving it four times was most of a q or p change |
| 2026-11-06 | A thing is declared once, and `use … through` draws it through a map | The lattice wrote every mark as `map(…)` and worked out sides again in every space, so `start` being one point was only a convention. Now it's one declaration. This replaces a `group` taking functions as arguments, which nothing needed after that |
| 2026-11-06 | A direction goes through a map by its exact derivative | A label's side is geometry in the group's coordinates, and the IR already has derivatives, so no step to tune. The lattice's differencing went away |
| 2026-11-06 | `text` gives a label's words per panel, and no text means no label | Kris: it's the same point, and the name is the space's. The spiral has one name for 0 and A, so A's label simply isn't there |
| 2026-11-06 | Where panels sit, and how far a label sits from its point, are a sheet's | A second sheet for the lattice, dark and one column, couldn't express them. The document keeps what's geometry: what a view looks at, and which way is out of the triangle |
| 2026-11-06 | The last definition of a sheet's name holds everywhere, even in rules before it | The dark sheet went last and silently did nothing. Now a theme only has to redefine its colors |
| 2026-11-06 | Hot loops run through `fast.rs`, with `eval` as the definition | A frame evaluates thousands of times, and resolving names first took this figure from 20 ms to under 8. A test requires them to agree to the bit |
| 2026-11-06 | A thing keeps its name across panels, and only its label's text is the space's | Kris: 0 and 1 are one point in different spaces, and connections like that are worth keeping |
| 2026-11-06 | A group's parameters are scoped to each use, and `use … as` prefixes what it declares | Log space draws the same edges three times, and two groups in one panel both wanted a `map` |
| 2026-11-06 | A curve's arrowhead is a style, with its stroke stopping inside the head | The same mark as the curve, and the blog's construction: the head points along the chord, so it stays on the line where the curve bends |
| 2026-11-06 | A label's text holds values as `{expr}` | The counts on the edges follow q and p, and the text is otherwise as written |
| 2026-11-05 | `solve` starts over each frame, and failure is absence | A frame stays a function of its inputs, and a figure with no solution shows nothing instead of garbage |
| 2026-11-05 | Newton's method uses symbolic derivatives | The IR already has them, so no finite-difference step to tune. The site's uses central differences |
| 2026-11-05 | A figure remembers a system's last answer, keyed by everything it depends on | A frame reads its bindings several times, and this can't change what's shown |
| 2026-11-05 | A collection is one mark, drawn through coverage layers | Hundreds of circles can't each be a block of shader and a uniform, and the count has to be able to change |
| 2026-11-05 | A variable's range includes both ends | Lattices are written that way, and `1..n` should have n in it |
| 2026-11-05 | A panel is its own scene, on one shared canvas | WebGL2 can't share a device across canvases, and a video needs one canvas anyway |
| 2026-11-05 | A `group` takes functions as arguments, replaced by `through` on 2026-11-06 | "A figure is a composition of functions": the same marks through a different map is what a panel usually is |
| 2026-11-05 | Expressions are lists of states, with identity in what's written | Manim's result, where what matches moves and only the rest fades, without its diff. Kris on the placement in `lab/expressions`: "beautiful" |
| 2026-11-05 | Moves use `snap`, a power of 5 | Kris wants a move to get there fast and leave time to take it in. Above 5, `za` joining `+zbi` goes by too quickly to see. The blog's is 4 |
| 2026-11-05 | Core lays out terms with widths from the renderer | The matching is the language's, and the fonts are the renderer's. It comes out as ordinary labels |
| 2026-11-05 | A step is a param, and `timeline` only one way to drive it | Same model as beats and sliders, so the arrows and the labels can bind to one number |
| 2026-11-05 | Labels move by settling springs, with a second spring on top | Kris chose it by eye in `lab/labels`: the placer jumps, a spring on the placer looks indecisive, and settling alone is wiggly |
| 2026-11-05 | Placement estimates text width from its length | It's soft anyway, and a page and a video then agree without sharing fonts |
| 2026-11-05 | A label's spring runs over earlier times in video, and over the clock on a page | A drag has no time axis, and a video's frames must not depend on order |
| 2026-11-05 | `show` uses the same per-frame flag as absent values | One way to be not there, and a hidden mark skips its shader work |
| 2026-11-05 | A construction's circle follows its own path when it needs a line | Tracing one for its dashes cost 12.7 ms a frame, for a path it already knew |
| 2026-11-05 | `which` names a root, not a place among the points left | One formula per root, so nothing jumps when a ray's start enters a circle. This replaced "a ray from inside has one point, and it's both 0 and 1" |
| 2026-11-05 | A ray means a ray when intersecting lines too | A point behind its start isn't on it. `bounds.pen` came out identical, so nothing relied on the old reading |
| 2026-11-05 | A value's existence is an explicit condition in the IR (`Where`), not NaN | NaN can't tell a missing point from a bug, `min` and `max` swallow it, and WGSL leaves it undefined |
| 2026-11-05 | Existence is decided on the CPU per frame, and the shader gets a flag per mark | No partial values reach the GPU, and a vanished mark skips its shader work |
| 2026-11-05 | `exists` and `otherwise` are the only way to see absence | Everything else propagates it, so a figure can't half-use a value that isn't there |
| 2026-11-05 | `self.age` is substituted per mark at compile time | One style rule fades every beat, and the runtime needs nothing new |
| 2026-11-05 | A beat is a discrete param, not a separate timeline feature | Same model as time and sliders, so video and buttons both just bind it |
| 2026-11-05 | A dragged param uses `bind` plus an override, like time and a slider | Sliders and drags need no new mechanism, and `q` can set θ through its binding |
| 2026-11-05 | `handle` takes an explicit inverse, and the param's range is the constraint | SPEC/16's explicit grade. Automatic inverses wait until something needs them |
| 2026-11-05 | Constructions lower to named scalars | Stays symbolic and costs little per frame, and circles get exact distance fields for free |
| 2026-11-05 | A `fit` view ignores handle-driven params | A drag mustn't rescale the figure under the pointer, as on the blog |
| 2026-11-05 | `font` names a role, not a typeface | Fonts differ per renderer, and naming real fonts is still open |
| 2026-11-05 | `viewport { width }` makes `px` scale with the output | The blog's sizes are in drawing units, and video needs the same look at any size |
| 2026-11-05 | Marks keep their written form, and `draw` is a hint | Normalizing costs about 50× on the same circle, and a hint can't change meaning (tested) |
| 2026-11-05 | Edges blend in gamma space by default | SVG's look is the bar, and linear visibly thins dark lines |
| 2026-07-08 | `::inside` is the negative side, with counterclockwise positive | Kris's convention, matching SDFs and Green's theorem. From the July 8 chat |
| 2026-07-08 | Style values are expressions | Fills can animate, and `self.dist` needs no special mechanism. From the July 8 chat |
| 2026-07-08 | Layers and order, with no specificity | SPEC/15 |
| 2026-07-08 | Only named bindings can be styled | SPEC/15 |

## Not built from the specs

`SPEC/15`: path selectors, `in clip(…)`, `:hover`, styling one instance of a collection by its key, branch labels with continuity
tracking, `:appearing`, `:vanishing` and `on appear: fade`. `SPEC/16`: relations, rigs, automatic inverses. `PLAN`: charts, modules (`use`,
`expose`), timelines with clips, profiles, the print round-trip, Unicode name normalization.
Also not built: `orient ccw` and `reverse`.
